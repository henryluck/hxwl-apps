### 需求 7：天气获取不到 —— App 内真正根因是解析器格式不匹配
- 接口链路本身早就通了（AES 新密钥 + HTTP 200），日志确认模拟器 4 个请求全部 `finished successfully`。
- **根因：服务端上游已升级为和风 v1 新格式**（`temperature.value` / `condition.code` / `hours[].forecastTime` / `days[].temperatureMax.value` / `astro.sunrise` 完整 ISO），而 `NavWeatherParser` 还按 v7 老格式解析（`now.temp` / `hourly[].fxTime` / `daily[].tempMax`）→ `parseCurrent` 取不到 `temp` 返回 nil → 整页报失败。
- 修复 `NavGateway.swift`：解析器兼容 v1/v7 双格式：
  - `wrappedNum`：`{"value":16.8}` 或裸数字
  - `wrappedCode(value, in: root, fallbackKey:)`：`{"code":"100"}` 或 root 上的 icon/iconDay（注意 v7 无 condition 时必须回退 root 的 fallbackKey，第一版漏了被单测抓到）
  - 湿度归一：>1 是 v7 百分数，0..1 是 v1 比例 ×100
  - v1 风速 m/s ×3.6 → km/h（界面按 km/h 展示）
  - v1 的 `astro.sunrise/sunset` 是完整 ISO 时间戳直接 parseISO；v7 是 HH:mm 走 parseTimeOnly
- 新建 `Packages/NavKit/Tests/NavKitTests/NavWeatherParserTests.swift`（4 测试：v1 实况/逐小时逐日/v7 回归/缺温度返 nil），`Package.swift` 加 testTarget。**NavKit 包单测要在 `Packages/NavKit` 目录下用 SPM 自动生成的 scheme 跑**（主工程的 NavKit scheme 没有 test action）。

- `simctl privacy grant location` 在此版本不生效（弹窗照出）；**可用方案：直接写 TCC.db**：
  ```sql
  INSERT OR REPLACE INTO access (service,client,client_type,auth_value,auth_reason,auth_version,csreq,policy_id,indirect_object_identifier,indirect_object_code_identity,flags,last_modified,pid,pid_version,boot_uuid,last_reminded)

  ```
  参照系统应用整行复制（含 csreq/policy_id），**写完必须 shutdown+boot 重启模拟器才生效**。locationd 启动时缓存授权。
