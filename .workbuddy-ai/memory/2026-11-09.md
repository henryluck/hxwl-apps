## 订阅页「正在确认会员方案」卡死排查与修复

现象：订阅页停在「正在确认会员方案」+ 重新检查、CTA 禁用，看起来像报错，实为 `introOfferState == .unknown` 降级态（需求规定 unknown 不按新人展示首期价）。

根因三层：
1. 环境（模拟器直接原因）：StoreKit 日志 `ASDErrorDomain Code=509 "No active account"`，未登录沙盒账号 + 工程无 `.storekit` 配置 → `Product.products(for:)` 返回空 → 资格恒 unknown。工程里目前**没有**任何 .storekit 文件。
2. 代码 bug A：「重新检查」只调 `refreshEntitlement()`，不重拉商品；首次商品请求失败后永远无法自愈（CTA 又禁用，无法走 purchase 里的补加载）。
3. 代码 bug B：`PaywallView` 以 `let pay: any PayService` 传入（非被观察对象），`AnyPayService` 也不转发 `objectWillChange`；商品异步到货后资格变 available/unavailable，页面不会重绘，仍停在 unknown 卡。

修复：
- `Capabilities.swift`：`PayService` 协议新增 `reloadProducts()`，`NullPayService` 空实现、`AnyPayService` 转发
- `PayService.swift`：`StoreKitPayService.reloadProducts()` = `loadProducts()` + `refreshEntitlement()`；商品为空/失败/资格 unknown 时补明确诊断日志（含请求 IDs、active 商品、已加载数量）
- `PaywallView.swift`：新增 `@State resolvedEligibility`，`eligibility` 优先读它；body 加 `.task` 进入页面主动核验；`recheck()` 改走 `resolveEligibility()`（真重拉商品）；失败态副标题改「暂时无法获取商品信息，请检查网络或 Apple 账户后重试。」（标题仍为需求口径「正在确认会员方案」）
- README 补根因与自愈说明

验证：`xcodebuild -project FactoryCore.xcodeproj -scheme FactoryCore -destination 'generic/platform=iOS Simulator' -derivedDataPath DerivedData build` 通过；Capabilities 包 16 个单测全过；模拟器装新包后日志可见同轮启动两次 `Starting product request`（init + 订阅页 .task），截图确认新文案与禁用 CTA。

坑：用 `xcrun simctl launch <udid> <bid> SIMCTL_CHILD_PAY_DEBUG_OPEN=1` 传环境变量经常不生效；可靠做法是 `xcrun simctl spawn <udid> launchctl setenv PAY_DEBUG_OPEN 1` 后重启 App，**用完必须 `launchctl unsetenv`**，否则每次启动都弹订阅页。

## 本地 StoreKit 商品配置（对齐用户给的 ASC 清单）

用户给了 5 个商品的正式清单（B 5.8/58 默认、D 1.8/48、C 8/48、A 0/58、终身 188），与 `spec.json` 的 `monetization` / `weekly_plans` **完全一致**，A 的 0/58 在 spec 里是 3 天免费试用（`trial_days: 3`）。spec 无需改动。

新增 `Resources/Products.storekit`（Xcode StoreKit Configuration v3）：1 个 NonConsumable + 4 个 RecurringSubscription，四个周商品各在**独立订阅组**（首期资格按组判定，待用户核对 ASC 实际分组），`settings._storefront=CHN` / `_locale=zh_CN`，首期优惠 `paymentMode=payUpFront`（A 为 `free` + `P3D`）。Xcode 打开实测能正确解析出全部商品与分组。

接入方式：`project.yml` → `targets.FactoryCore.scheme.storeKitConfiguration: Resources/Products.storekit` + sources 里 `buildPhase: none` 挂文件引用。xcodegen 2.46.0（本机 `/Users/gx/.local/bin/xcodegen`，PATH 里没有）支持该字段，生成 `FactoryCore.xcodeproj/xcshareddata/xcschemes/FactoryCore.xcscheme` 的 `StoreKitConfigurationFileReference = ../../Resources/Products.storekit`。

关键结论：**StoreKit 配置只在 Xcode ⌘R 时由 Xcode 推送给模拟器 storekitd；`xcodebuild` + `simctl install/launch` 不注入**。实测命令行装新包后仍是 `ASDErrorDomain 509 No active account`、商品 0 个。Apple 论坛亦确认 xcodebuild test 不推 `StoreKitConfigurationFileReference` 到 storekitd AppGroup。

坑：
- 重新跑 xcodegen 会重建 pbxproj，冲掉旧文件里的默认 build settings 和 `CODE_SIGN_IDENTITY` / `DEVELOPMENT_TEAM` / `PRODUCT_NAME`（旧名 智能卫星导航）；已在 project.yml settings.base 补回 `ALWAYS_SEARCH_USER_PATHS: NO`（消除 headermap 警告）、`CODE_SIGN_IDENTITY`、`DEVELOPMENT_TEAM`。产物名现为 `智能卫星定位.app`（符合改名）
- Xcode 首次打开工程可能显示 `Unable to find module dependency: CoreKit` 等，命令行 build 正常，需 File → Packages → Resolve Package Versions
- AppleScript 驱动 Xcode ⌘R 在本机 System Events 超时，没能自动完成 Xcode Run 的端到端验证

## 复验结论（收尾）

- 全量重跑：主工程 `xcodebuild ... build` → `** BUILD SUCCEEDED **`（产物 `智能卫星定位.app`，arm64+x86_64 通用二进制）；Capabilities 包 `xcodebuild test -scheme Capabilities -destination 'platform=iOS Simulator,name=iPhone 17 Pro'` → `Executed 16 tests, with 0 failures` / `** TEST SUCCEEDED **`
- `.storekit` 与 `spec.json` 商品 ID 机器比对一致（5 个 ID：unlimited / weekly / weekly.sale / weekly.deal / weekly.offer）；`paymentMode` 确认为 `payUpFront` / `free`（Xcode 配置值，非 StoreKit API 的 `freeTrial`）
- 命令行确实无解：`xcodebuild -help`、`xcrun simctl help` 都没有 storekit 相关参数，Xcode 内也没有可调用的 storekit CLI。注入由 `IDEFoundation` 的 `handleStoreKitConfigurationSyncForBundleID:configurationFilePath:runsOnProxy:`（日志串 "StoreKit Configuration sync"）在 IDE 启动 App 时完成 —— 属 IDE 行为，不是 scheme 文件本身的能力，所以只能 ⌘R
- 已确认无 `xcuserdata/*/xcschemes/*.xcscheme` 覆盖共享 scheme，`StoreKitConfigurationFileReference` 在 `LaunchAction` 内会真实生效
- 唯一遗留：Xcode GUI ⌘R 的端到端「商品加载成功 → 订阅页可购买」需人工验证；这是机制限制，不是配置错误
