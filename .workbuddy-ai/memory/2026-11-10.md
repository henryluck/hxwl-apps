## 修复 Xcode GUI `Unable to find module dependency`（xcodegen 重建 pbxproj 的副作用）

用户报 Xcode GUI 里 `Sources/FactoryApp.swift:1:8 Unable to find module dependency: 'BaseComponents'` / `'Capabilities'`、`PluginRegistry.swift` 的 `'NavKit'`，并带 `AppSpec.swift` 的 `'CoreKit'`。**不是索引器缓存，也不是包没解析**：从 Xcode GUI 的 DerivedData（`~/Library/Developer/Xcode/DerivedData/FactoryCore-cpnevctycugsdheyuyzxohvzkcbc`）里 `Logs/Build/*.xcactivitylog`（gzip，用 `gunzip -c | strings` 读）确认是真实的 Swift Compiler Error，`** BUILD FAILED **`。之前建议的 File → Packages → Resolve Package Versions 是错的，README 已改正。

根因（架构不一致）：
- `xcodegen generate` 重建 pbxproj 时冲掉了 Xcode 模板的默认 build settings，其中 Debug 的 `ONLY_ACTIVE_ARCH = YES` 变成缺省 `NO`。`xcodebuild -showBuildSettings` 两种 destination 下都显示 `ARCHS = arm64 x86_64` / `ONLY_ACTIVE_ARCH = NO`。
- 具体模拟器 destination（`platform=iOS Simulator,name=iPhone 17 Pro`）下，主 target 编 arm64 + x86_64，但本地 SPM 包 target 在 Debug 只产出 arm64 的 `.swiftmodule`（GUI 日志里 `Objects-normal/arm64/{CoreKit,Capabilities,BaseComponents,NavKit}.swiftmodule`，无 x86_64）→ x86_64 那次 SwiftDriver 找不到模块。
- `generic/platform=iOS Simulator` 下所有 target 都编双架构（日志里有各包 `.o` 的 `CreateUniversalBinary ... arm64 x86_64`），所以命令行构建一直成功，把问题掩盖了。之前只用 generic 验证是漏测点。

修复：`project.yml` → `targets.FactoryCore.settings.configs` 新增 Debug/Release 分配置：
- Debug：`ONLY_ACTIVE_ARCH: YES`、`SWIFT_ACTIVE_COMPILATION_CONDITIONS: DEBUG`、`ENABLE_TESTABILITY: YES`、`DEBUG_INFORMATION_FORMAT: dwarf`
- Release：`ONLY_ACTIVE_ARCH: NO`
- base 里原有的 `ALWAYS_SEARCH_USER_PATHS` / `CODE_SIGN_IDENTITY` / `DEVELOPMENT_TEAM` 保持

顺带发现并修复第二个被静默破坏的功能：**`SWIFT_ACTIVE_COMPILATION_CONDITIONS = DEBUG` 被冲掉后，主 target 的 `#if DEBUG` 被整体裁掉**，`ShellRootView.swift:73` 的 `PAY_DEBUG_OPEN` / `PAY_DEBUG_VARIANT` 调试入口失效。验证方法：`LC_ALL=C strings -a <Debug app 二进制> | grep -o "PAY_DEBUG_[A-Z_]*"` —— 修复前只有来自 SPM 包的 `PAY_DEBUG_ELIGIBILITY`，补回后主 target 的 `PAY_DEBUG_VARIANT` 也出现。（注意 `PAY_DEBUG_OPEN` 字面量在 -Osize 下不以完整 NUL 结尾字符串出现，别用它当判据。）

验证（全部用全新 DerivedData clean build）：
- 具体模拟器 destination：`** BUILD SUCCEEDED **`，主 target 只剩 `SwiftDriver FactoryCore normal arm64`
- generic destination：`** BUILD SUCCEEDED **`，产物 `lipo -info` = `x86_64 arm64`（出包路径未受影响）
- Capabilities 包：`Executed 16 tests, with 0 failures` / `** TEST SUCCEEDED **`
- xcodegen 重建后 scheme 的 `StoreKitConfigurationFileReference` 仍在（grep -c = 2）

经验：
- 排查 GUI 与命令行构建不一致，优先 `gunzip -c <DerivedData>/Logs/Build/*.xcactivitylog | strings | grep -E "error:|BUILD FAILED"`，别猜缓存
- 复现 Xcode GUI 行为要用**具体设备 destination** + 全新 DerivedData，`generic/platform=` 会改变所有 target 的架构行为
- 改 `project.yml` 后必须 `/Users/gx/.local/bin/xcodegen generate --spec project.yml`（PATH 无 xcodegen），并提示用户在 Xcode 里 ⇧⌘K 清旧缓存

## 去掉地图上的「高德地图」水印（MapKit，非高德 SDK）

用户给参考文件 `/Users/gx/apps-dev/导航/去掉高德logo的方法.md`，要求去掉当前 App 的高德 logo。参考工程用的是高德 iOS SDK（`MAMapView.logoEnable` / `AMapNaviDriveView`），**当前工程是 Apple MapKit `MKMapView`**：`NavKit/Package.swift` 无 AMap 依赖，spec 的 amap key 只是预留，不能照搬 `logoEnable`。水印是 MapKit 中国区使用高德数据时自带的右下角描边 logo。

新建 `Packages/NavKit/Sources/NavKit/MapBranding.swift`，在 `MapView.makeUIView` / `updateUIView`（图层切换）接入 `MapBranding.apply(to: map)`：
- 多信号命中：类名含 logo / 图片描述含 logo|amap|autonavi / `UIImageView` 宽 40~110pt 且 `h <= w/2.2` / 文字含「高德」或 AMap
- 时序：0 / 0.5 / 1.5 / 3.0s 四拍 + 每 3s 弱引用自终止巡检（关联对象 `sweepKey` 去重，避免图层切换重复挂链；`hide(in:log: false)` 静默巡检不刷日志）
- 只设 `isHidden`/`alpha`，不 `removeFromSuperview`；保留 `MKAttributionLabel`（Apple Legal/归属入口）降低条款风险
- 合规降级：`compliantMinimize(in:)` 缩到 10% + alpha 0.35，不隐藏

关键实测（踩坑）：
- `LOGO_DEBUG=1` dump 出真实层级：`MKMapView` 直接子视图 `UIImageView (46x10)`（图片 anonymous 无名称）= 高德 logo，`MKAttributionLabel (29x11)` = Apple Legal
- 第一版按 `attribution` 类名命中 + 尺寸下界 55pt，只藏掉 Legal；截图裁剪 md5 与原始版完全相同 → 判定无效。参考文档的 70pt 判据在 MapKit 上不适用，必须放到 40pt
- 编译报错 `NSStringFromCGSize has been replaced by 'NSCoder.string(for:)'` → 改为直接 `%.0fx%.0f` 格式化 width/height
- 调试变量要用 `xcrun simctl spawn <UDID> launchctl setenv/unsetenv LOGO_DEBUG`，`SIMCTL_CHILD_` 不可靠

验证：修正后四拍均 `HIT size -> UIImageView (46x10)`；主工程 `** BUILD SUCCEEDED **`，Capabilities `16 tests / 0 failures`；右侧裁剪放大图原始版 md5 `0f4a...`、修正版与最终版同为 `ed00...`，启动 9s 后（越过四拍 + 首轮巡检）水印仍消失。清理了 `LOGO_DEBUG` 并停掉后台 `simctl launch --console` 任务。

**遗留合规项**：MapKit 归属标注受 Apple MapKit 服务条款约束，与高德 SDK 商务授权不等价；参考文档以「已获高德授权」为前提。当前实现是直接隐藏，上架前需法务确认，否则改用 `compliantMinimize`。已写入 README 新章节「地图品牌水印（MapKit 中国区「高德地图」）」。
